# Трекер отжиманий: концепт проекта

Документ для Claude Code. Здесь описано, что строим, зачем, на чём и какие решения уже приняты. Вопросы, на которые ещё нет ответа, собраны в конце: начни с них.

## 1. Зачем это нужно

Арсений хочет отжиматься каждый день, чтобы набрать мышечную массу. Ему нужен личный трекер привычки: записывать подходы, видеть цель на сегодня, не рвать цепочку дней.

Готовые приложения не подошли: нужен бесплатный вариант с записью числа повторов и веса рюкзака, а не просто галочка. Решено сделать свой сайт «на коленке» и разместить на своём VPS.

Пользователь один. Основное устройство: iPhone, сайт добавляется на домашний экран через Safari. Данные должны переживать очистку браузера и быть доступны с других устройств, поэтому хранятся на сервере, а не в localStorage.

## 2. Исходные данные пользователя

- Максимум за подход сейчас: 20–40 повторов (для расчётов принято 30)
- Время на тренировку: 10–15 минут в день
- Инвентарь: пол и рюкзак с утяжелением (книги, бутылки с водой)
- Дата старта программы: 21 сентября 2026 (понедельник)
- Часовой пояс: Europe/Moscow. Границу дня считать по локальной дате устройства

## 3. Тренировочный план (это данные приложения)

Вынеси план в отдельный конфиг (JS-объект или JSON), чтобы его можно было править без переписывания логики.

### Типы отжиманий

| Ключ | Название | Акцент |
|---|---|---|
| `classic` | Классические | грудь и трицепс, база |
| `weighted` | С рюкзаком | главный инструмент для массы |
| `decline` | Ноги на возвышении | верх груди и плечи |
| `diamond` | Алмазные (узкие) | трицепс |
| `wide` | Широкие | грудь |
| `slow` | Медленные (3 сек вниз, пауза внизу) | усложнение без веса |

### Расписание по дням недели

Отдых между подходами 60–90 секунд.

| День | Тип дня | Что делать |
|---|---|---|
| Пн, Чт | Тяжёлый | С рюкзаком, 4 подхода по 8–15, останавливаться за 1–2 повтора до отказа |
| Вт, Пт | Объём | Классические, 4–5 подходов по 60–70% от максимума |
| Ср, Сб | Вариации | Ноги на возвышении 3 подхода + алмазные 3 подхода |
| Вс | Лёгкий | 2 подхода по половине максимума, либо отдых |

### Прогрессия по неделям

| Недели | Цель повторов в день | Вес рюкзака |
|---|---|---|
| 1–2 | 80 | 5 кг |
| 3–4 | 100 | 7–8 кг |
| 5–6 | 120 | 10 кг |
| 7–8 | 140 | 12 кг |
| 9–12 | 140 (в обсуждении не расписано, значение по умолчанию) | рост до 15 кг |

Итоговая цель к 12-й неделе: 50 повторов подряд без веса или 20 повторов с рюкзаком 15 кг.

### Правила

- Каждые 4 недели тест на максимум. После теста пересчитываются подходы в днях «Объём» и «Лёгкий»
- Если в тяжёлый день легко выходит 15 повторов во всех подходах, вес рюкзака +2 кг
- Никогда не пропускать два дня подряд
- В плохой день минимум: 1 подход из 10 повторов. Такой день засчитывается в цепочку

## 4. Что должно уметь приложение

### Главный экран (сегодня)

- Тип дня и подсказка, что делать (из расписания)
- Цель на сегодня и сколько уже сделано, прогресс виден сразу
- Быстрая запись подхода: кнопки `+10`, `+15`, `+20` и поле для своего числа
- Выбор типа отжиманий (по умолчанию тот, что положен по расписанию)
- Поле веса рюкзака, подставляется последнее значение
- Список подходов за сегодня, любой можно удалить или исправить
- Текущая цепочка дней (стрик) и рекорд цепочки

### История

- Календарь-теплокарта по дням: чем больше повторов, тем ярче клетка
- Сумма за неделю и за всё время
- График максимума по результатам тестов
- История веса рюкзака

### Прочее

- Напоминание о тесте на максимум раз в 4 недели (баннер в интерфейсе)
- Экспорт всех данных в JSON и импорт обратно
- Вход по логину и паролю, сессия долгая, чтобы не вводить каждый день
- Светлая и тёмная тема по настройкам системы

### Чего делать не надо

- Push-уведомлений. На iPhone из веб-сайта они ненадёжны, напоминания закрываются отдельно через приложение Reminders
- Регистрации, нескольких пользователей, социальных функций
- Сборщиков, фреймворков и npm-зависимостей на фронте

## 5. Технические решения

### Стек

- **Бэкенд и база: PocketBase.** Один бинарник, внутри SQLite, авторизация, REST API и админка. Он же раздаёт статику из `pb_public`
- **Фронт:** один `index.html` с встроенными CSS и JS, без сборки. PocketBase JS SDK можно подключить одним файлом
- **HTTPS: Caddy** как reverse proxy с автоматическим сертификатом. HTTPS обязателен, иначе сайт нормально не добавится на домашний экран iPhone
- **Запуск:** systemd-юнит для PocketBase, автозапуск после перезагрузки

### Модель данных (коллекции PocketBase)

**`sets`** — подходы
- `user` — relation на users
- `date` — строка `YYYY-MM-DD`, локальная дата устройства
- `reps` — число, обязательное, больше 0
- `type` — select: `classic`, `weighted`, `decline`, `diamond`, `wide`, `slow`
- `weight_kg` — число, необязательное

**`max_tests`** — тесты на максимум
- `user`, `date`, `reps`

**`settings`** — одна запись на пользователя
- `user`, `start_date`, `current_max`, `backpack_kg`

API-правила для всех коллекций: доступ только к своим записям (`user = @request.auth.id`). Публичная регистрация выключена, пользователь создаётся вручную через админку.

### Вёрстка

- Mobile-first под iPhone, крупные кнопки под большой палец
- `viewport-fit=cover` и отступы через `env(safe-area-inset-*)`
- Манифест и иконка, чтобы с домашнего экрана открывалось без панелей Safari
- Желательно: если сети нет, подход сохраняется в очередь в localStorage и отправляется при следующем открытии

## 6. Размещение

Сервер: существующий VPS Арсения, на котором работает его VPN. Отдельный сервер не покупаем.

### Жёсткие ограничения

- **VPN не ломать.** Не менять конфиги VPN, firewall и занятые порты без явного подтверждения. Перед любой правкой чужого конфига делать его копию
- Сначала диагностика, потом план, потом установка

### Диагностика (только чтение)

```bash
head -2 /etc/os-release; ss -tulpn | grep -E ':(80|443) '; free -h | head -2; df -h / | tail -1
```

### Развилка по порту 443

- **443 свободен** (например, на сервере только IKEv2, он использует UDP 500/4500): Caddy садится на 80 и 443, проксирует на PocketBase на `127.0.0.1:8090`
- **443 занят Xray с Reality:** два варианта, выбрать вместе с Арсением
  - Caddy на другом порту (например 8443), сертификат получает через порт 80
  - Xray отдаёт трафик на Caddy как fallback, Caddy слушает только localhost

### Домен

Нужен поддомен, направленный на IP сервера (например `pushups.домен.ru`). Если домена нет, использовать бесплатный адрес вида `1-2-3-4.sslip.io`.

### Бэкапы

Ежедневная копия базы: встроенные бэкапы PocketBase по расписанию или cron с `sqlite3 .backup`. Хранить последние 14 копий. Переезд на другой сервер должен занимать минуты: бинарник, папка `pb_data`, Caddyfile.

### Известный риск

Если IP сервера заблокируют как VPN, трекер станет недоступен вместе с ним. Для личного инструмента это принято как допустимое. Страховка: бэкапы и экспорт в JSON.

### Безопасность

- Сильный пароль на админку PocketBase (`/_/`)
- PocketBase слушает только `127.0.0.1`, наружу смотрит только Caddy
- Никаких секретов в репозитории

## 7. Рассмотренные и отклонённые варианты

| Вариант | Почему нет |
|---|---|
| Готовые приложения (Habitify, Habitica, Loop, Streaks) | Streaks платный, Loop только Android, остальные не ведут вес рюкзака; захотелось своё |
| Только localStorage | Данные пропадают при очистке Safari и не переносятся между устройствами |
| GitHub Pages + Supabase | На бесплатном тарифе репозиторий обязан быть публичным, нужен внешний сервис |
| Vercel + внешняя база | Избыточно для одной страницы, возможны перебои доступа из РФ |
| Артефакт Claude | Рабочий, но выбран собственный сервер ради полного контроля |

## 8. Критерии готовности

- Сайт открывается по HTTPS с iPhone и добавляется на домашний экран
- Вход один раз, дальше сессия сохраняется
- Подход записывается в два касания
- Цель дня, тип дня и вес рюкзака соответствуют плану и дате старта
- Стрик считается верно, включая «минимальные» дни
- Данные видны с другого устройства после входа
- Экспорт и импорт JSON работают
- После перезагрузки сервера всё поднимается само
- Бэкап создаётся ежедневно
- VPN на сервере работает как раньше
